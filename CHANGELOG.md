# Changelog

All notable changes to MTAutoDraw are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project uses
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

MTAutoDraw's libraries are dot-sourced `.ps1` files imported by path, not a sealed module. Anything
you can call, you can call from your own script — which means a removed function is a breaking
change for you even though it was never part of a published API. Every removal is therefore listed
by name under **Removed**.

## [Unreleased]

### Added

**A graphical front-end: `MTAutoDraw.cmd`.** Running the tool previously meant a terminal, three path
parameters, and editing `configurationVariables.ps1` to change anything. The GUI is a WinForms window
with five tabs — Run, Advanced, Log, Results, Setup — that picks folders, edits settings, streams the
run, and shows the verdict.

It is a launcher, not a host: it runs `AutoDraw.ps1` as a **child process** and reads its output and
`RunSummary.json`. Nothing in the pipeline depends on it, and `GuiSettings.ps1` is deliberately not in
`$GLibrariesToLoad`. The command line is unchanged and remains fully supported.

- **Run tab** — the 26 settings that change what you get, grouped and labelled in the language of the
  output. Save and load named profiles.
- **Advanced tab** — every remaining setting, generated by parsing `configurationVariables.ps1` with
  the PowerShell AST so the tab cannot drift from the file, using each setting's own comment block as
  its help text. A newly added setting must be either surfaced or explicitly skipped; neither is
  not an option.
- **Setup tab** — checks PowerShell 7, the Python interpreter, `textfsm`, `TextFSM.py`, the templates
  and `GetIPv4Subnet`, each with the fix for it. A fresh clone has no interpreter, so **Set up Python**
  downloads an embeddable build and installs `textfsm`; every download is confirmed first by URL,
  filename and size, and only the gitignored `python\` folder is written to.
- **Results tab** — verdict, counts, problems, and every file produced, with Open buttons.

The Log tab reads the child process with plain .NET `ReadAsync`, polled from a WinForms timer, rather
than `Register-ObjectEvent`. A PowerShell `-Action` handler only runs when the engine is idle, and
`ShowDialog()` holds the engine inside one statement for the life of the window — measured on an
11-second run, the eventing version delivered nothing at all until the window closed. Note when
testing this that a `DoEvents` pump does not reproduce the failure, because it lets the engine go
idle between pumps. Verifying it needs a real `ShowDialog`, checking that output arrives in several
batches, early.

**`AutoDraw.ps1 -SettingsPath <file.json>`.** Setting overrides applied on top of
`configurationVariables.ps1`, e.g. `{ "GDrawPhysical": false }`. A profile saved by the GUI nests the
same pairs under `Settings` and is accepted unmodified, so profiles work from the command line too.

Applied after the library load — where the configuration file's own defaults would otherwise win —
but before the command line is reasserted, so `-LogLevel` and `-Quiet` still outrank a settings file.
Only names that already exist are applied; an unknown key is reported and skipped. The file is
deserialized and assigned, never executed.

### Fixed

**Network Path Analysis can be loaded repeatedly in one PowerShell session.** Its C# performance
types are now reused after the first load instead of being compiled again, preventing duplicate
`NetworkAnalysisTools.*` type errors when AutoDraw is rerun from the same console or host process.

**Layer 3 detail and firewall relationship layouts.** `Layer 3 All` and `Layer 3 Routed Links Only`
now use two-pass, measured radial component placement for devices, subnets and ARP leaves. Interface
chips face their subnet peers, branches stay together, and annotations remain on the component edge.
Hosts collapse only when their full route behavior and visible CIDR set match; summaries retain every
hostname and interface/IP row.

`Layer 3 Routes Only` now draws only route-bearing groups and nodes used as route endpoints. Captured
target-only next hops use compact endpoint cards, summarized members are not drawn twice, and all
other route-less devices move to one sampled omitted-device footer. The model returns the target-only
and omitted collections explicitly.

`Layer 3 Connectivity` and `Layer 3 Routes Summary` now use size-aware landscape radial placement.
The Layer 3 routing role selects a captured Border/firewall, Transit, or Gateway centre before visible
relationship count, with an optional directly connected redundant pair. Straight, non-rounded route
arrows attach to node boundaries and stagger their labels; tall route summaries retain every member.
The route-summary hostname limit now defaults to `0` (unlimited), while saved positive caps retain
their preview behavior.

`FW Zone Hub` uses direct straight arrows. `FW NAT and Interfaces` draws only participants in parsed
NAT relationships, including connected unresolved placeholders; no NAT produces a note-only page.
Its three numbered columns, edge labels, legend, and footer explain source matching and translation
as processing order rather than return-traffic direction.

**Every configured device now gets its own card on the Topology Overview.** End-unit collapsing
folded any node with a single link into a dashed box per parent, without distinguishing a device
whose config we parsed from a CDP/LLDP neighbour we merely overheard. On a large site that could
hide a third of the page — parsed devices boxed up beside access points, with no way for
the reader to tell the two apart. `Get-MTAutoDrawEndUnitGroups` now takes `-CollapsibleKeys` and only
observed peers and inferred-evidence nodes are eligible; a parsed device keeps its own card whatever
its degree. The box is relabelled "N uncaptured neighbours", which is now exactly what it holds.

**Capture commands are matched without regard to hyphens.** Capture filenames carry the command
verbatim, so a real file named `HOST.show.running-config.brief.txt` produced the key
`show running-config brief` while the registry spelt it `show running config brief` — and the lookup
was an exact hashtable hit, so the file was discarded. The drop was recorded only as an `Info`
diagnostic that nothing printed. Four commands were affected, and every capture file of those
commands was silently dropped:

- `show running-config brief` — cost those devices their hostname, so they fell back to being named
  by their management address, along with their whole running config: interface stanzas, VLAN
  database, spanning-tree mode and port descriptions.
- `show spanning-tree interface detail` — every Junos switch lost its per-port spanning-tree data.
  Junos interface rows in `interfaces.csv` now carry an STP role/state that were blank before, and
  that is the input the inferred-topology evidence is built from.
- `show ethernet-switching table detail` / `... extensive` — now mapped, though not yet
  parsed: on Junos 22.4 both emit the `<l2ng-l2ald-rtb-macdb>` schema while
  `Update-JunosMacAddressTable` reads the older `ethernet-switching-table-information` one, so Junos
  MAC/CAM data is still empty. The capture reaching the parser is the prerequisite for fixing that.

`show ethernet-switching table` and `show spanning-tree interface` variants now carry explicit
priorities, so a device holding several of them maps deterministically.

**A `CaptureCollision` is only a warning when it is genuinely ambiguous.** Two captures competing for
one slot at DIFFERENT priorities is the registry working as designed - every Junos switch carries both
`show ethernet-switching table detail` and `... extensive` - and used to raise a `Warning` each time,
which alone was enough to turn a run's verdict to `Warn`. That case is now `Info`. An EQUAL-priority
collision, where nothing but filename sort order picks the winner, is still a `Warning`.

### Added

**Unmapped capture commands are logged.** One line per distinct command with a file count, at the end
of capture grouping. This is the diagnostic whose absence let the hyphen bug above run unnoticed.

### Changed

**`Get-MTAutoDrawEndUnitGroups` takes a new mandatory `-CollapsibleKeys` parameter.** Breaking for
anyone calling it directly. `-Keys` must still be the full key set: degree and the parent test read
it, and narrowing it instead would change every parent's degree.

## [1.0.0] — 2026-08-24

The first tagged release. MTAutoDraw has been usable for a long time; this is the point at which it
became something a second person can work on. Most of the work below is not new behaviour but a
codebase where each section has one shape and a written contract to follow.

### Added

**Diagram pages.** Six one-screen overview pages, each deliberately scoped to a subset of the
network so it fits a single 1080p screen, with full detail always still available on the per-device
pages and in the exports:

- **Topology Overview** — icon-per-device physical map, tiered Core / Distribution / Access by
  resolved neighbour degree, placed by a radial engine that puts the most central device in the
  middle and fans everything else out by hop distance.
- **Layer 3 Topology Overview** — the routing analogue, tiering devices into Border / Transit /
  Gateway from routing data alone, with shared-subnet chips and one merged edge per device pair.
- **Layer 3 Connectivity** — which devices route through which upstream next hop, collapsing
  devices with identical routed-route sets into one node.
- **Layer 3 Routes Summary** — "who points where" on one screen.
- **Four per-firewall pages** — segmentation overview, NAT and interfaces, zone hub, and the rules
  worth arguing about, for CheckPoint, Cisco ASA, PaloAlto and FortiGate devices.

**Placement engine.** Topology placement is pluggable via `$GDrawioTopologyPlacementStrategy`, with
the radial starburst as the default.

**Exports.** `devices.csv`, `interfaces.csv`, `routes.csv`, `cidr.csv`, `CDPNeighbors.csv`,
`LLDPNeighbors.csv`, `layer3-interfaces.csv`, `topology-evidence.csv`, and `Objects.json`.

**`RunSummary.json`.** A machine-readable result for every run: a Pass / Warn / Fail verdict, a
process exit code, device and error counts, and the list of artifacts produced. The verdict is also
printed as the last line of the run.

**Version reporting.** `$GMTAutoDrawVersion` appears in `RunSummary.json` and on the verdict line,
so log output says which build produced it.

**Regression harness.** A single entry point runs module loading, parser conformance, label
escaping, the diagram-model assertions, layout and presentation checks, a smoke test over sanitized
captures, and a byte-exact render comparison against a recorded baseline.

### Changed

**All eleven vendor parsers conform to parser standard v1**
([`PARSER_STANDARD.md`](PARSER_STANDARD.md)), which is enforced
mechanically against every module. One shape for every module: one orchestrator that reads as a
list of captures, one guard, and readers that take exactly `-Device` and `-Path`.

**TextFSM fields are addressed by name, not position.** Every parser previously indexed template
output positionally — `$row[7]` — which breaks silently and invisibly when an upstream ntc-template
reorders its `Value` declarations. All 100+ such indices are gone.

**Helper libraries split by concern.** The former single `HelperFunctions.ps1` is now
`Logging.ps1`, `ParserRuntime.ps1`, `DrawioDocument.ps1`, `NeighborResolution.ps1`,
`LayoutMath.ps1`, `Exports.ps1` and `DiagramModels.ps1`.

**Every diagram page derives its data through a model.** Page functions place and draw; the
decisions about what to draw live in `DiagramModels.ps1` where they are asserted without rendering.

**One way to write a cell, one way to escape a label.** `Add-DrawioCell` is the only function that
writes into the Draw.io document, and the only one that HTML-escapes.

**One colour palette, keyed by role.** `Get-MTAutoDrawPalette` replaces 147 inline hex literals.
Changing how "external / not captured" looks is now one edit that reaches every page drawing one,
including its legend entry.

**Every page states its scope,** and no page can render blank — a page with nothing to show says
what it looked for and where the full detail lives.

### Fixed

- **FortiGate firewall policy was never parsed** when the capture's prompt had been stripped.
- **An unparseable TextFSM capture was treated as a parser error,** failing the whole run for one
  optional capture on one device. It is a warning.
- **A TextFSM template that legitimately matched zero rows was reported as unparseable,** and the
  capture was re-parsed against a prompt-stripped copy for nothing. An empty result is now a result.
- **The global network list was deduplicated non-deterministically,** so a device re-ordering its
  own network array silently reassigned ARP entries and connector counts to a different device's
  networks — moving names and vendor counts on the Layer 3 pages of unrelated devices.
- **Cisco Small Business CDP detail** is recognised in both the SG and CBS dialects.
- **SGE-LCLI bare-name captures** are recognised via directory IP fallback.
- **The Layer 3 Topology Overview legend showed a colour the page does not draw** — its routed
  adjacency swatch and the edges it explains were two different greys.
- **The Layer 3 dependant node was laid out at one size and drawn at another,** because the layout
  measured the member-name list and the drawing measured it after wrapping it in markup.
- **`Add-DrawioCell` dropped a geometry coordinate of zero,** because `0 -eq ''` is true in
  PowerShell and a missing attribute is not the same as a zero one.
- **The Layer 3 Topology Overview page rendered non-deterministically,** producing a different file
  from identical input.
- **A Cisco IOS interface held one secondary IPv4 address; a second `secondary` line silently
  replaced data nowhere, because the reader only ever captured the first.** IOS permits any number
  of `ip address ... secondary` lines. `Secondary(IPAddress|SubnetMask|Cidr)` are now parallel
  arrays - every consumer (the exports, `Get-MTAutoDrawInterfaceIPv4Address`,
  `NeighborResolution.ps1`) already read them that way, following the shape
  `PaloAltoConfigProcessingFunctions.ps1` used for its own multi-address continuation lines.
- **The Cisco IOS `show interface` reader took duplex, speed and media type one column to the right
  of their names,** so `Duplex` held the speed and `Speed` held the media type. The NX-OS branch was
  never affected.
- **A Cisco IOS static or other non-connected route could show its VRF name where its outgoing
  interface belonged,** reading `NEXTHOP_VRF` instead of `NEXTHOP_IF`. Visible only for a recursive
  next-hop that resolves to neither the connected-route back-fill nor the subnet-match lookup.
- **The IPv6 all-nodes multicast MAC (`3333.0000.000d`) was treated as a real neighbor on Cisco IOS,**
  while the same filter correctly dropped it on NX-OS and IOS-XE.

### Known limitations

- **`Network Path Analysis.ps1` is experimental** and disabled by default
  (`$GNetworkTracePathAnalysis = $false`). It has no regression coverage and was deliberately left
  out of the v1 standardisation.
